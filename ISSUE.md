# Артефакт 3. Git Issue

**Title:** Storage architecture v1 — Data Placement Map

---

## Решения

- **Пользователи:** PostgreSQL (источник истины) + Redis (кэш профиля, TTL 15 мин)
- **Сессии и токены:** Redis (access-сессии, TTL) + PostgreSQL (refresh-токены, отзыв доступа)
- **Курсы и уроки:** PostgreSQL (метаданные, права, статус) + MongoDB (тело курса: модули → уроки → материалы)
- **Прогресс по курсам:** PostgreSQL (hash-партиционирование по `course_id`) + Redis (кэш «на чём остановился», TTL 5 мин)
- **Поиск по курсам:** Elasticsearch (производный индекс, источник — PostgreSQL + MongoDB)
- **Форум / обсуждения:** PostgreSQL (`parent_id` + рекурсивный CTE) + Redis (счётчики лайков, сброс раз в минуту)
- **Логи действий:** Kafka (транспорт) → ClickHouse (партиции по дням, TTL 12 мес)
- **Аналитика и отчёты:** ClickHouse (материализованные представления как витрины)
- **Рекомендации курсов:** ClickHouse (ночной батч) → Redis `ZSET` (топ-20, витрина чтения)

## Открытые вопросы

1. **Публикация курса затрагивает PostgreSQL и MongoDB и не атомарна.** Достаточно ли
   outbox-паттерна, или стоит свернуть тело курса в PostgreSQL JSONB и убрать MongoDB из стека?
   Порог, на котором это перестаёт быть вопросом, — примерно 10 тыс. курсов.
2. **Прогресс — единственная сущность в OLTP с неограниченным ростом.** Какой порог считать
   триггером выноса в wide-column? Предлагаем 500 млн строк или p99 записи > 50 мс.
3. **Оправдан ли Elasticsearch ради одной сущности?** Требование «поиск с опечатками» его
   оправдывает, но цена — пятый компонент в стеке. Нужно решить, входит ли fuzzy-поиск
   в MVP или переносится на v2 (тогда на старте достаточно PostgreSQL FTS).
4. **Kafka на MVP.** До ~1000 событий/сек хватает буфера в приложении. Когда именно вводим Kafka —
   сразу или по достижении порога?
5. **Допустимое отставание витрин.** Договорились на 5 минут для оперативных отчётов и сутки
   для тяжёлых — нужно подтверждение от заказчика аналитики.
6. **Потеря лайков при падении Redis.** Приняли как допустимую. Требует явного согласования
   с продуктом, а не молчаливого решения разработчиков.
